# Ledgerly Version History

## v1.0.8
- วันที่: 2026-10-18
- ปรับปรุง: แยกหน้าเว็บเป็น component ย่อย เปิดหน้าเดิมหลัง refresh ด้วย hash routing และเปลี่ยน confirm ที่ใช้เดิมเป็น dialog ของระบบ
- รายละเอียด:
  - แยกฟอร์นต์เอนด์ออกจาก App.tsx เดิมเป็น component ต่อหน้า (Auth, Overview, Transactions, Accounts, Notification, Admin) และ dialog แยกไฟล์ พร้อม types/format ที่ใช้ร่วมกัน
  - เปลี่ยน URL hash (#/overview ฯลฯ) เป็นตัวกำหนดหน้าปัจจุบัน กด F5 หรือแชร์ลิงก์กลับมาหน้าเดิมได้ทันที
  - การลบรายการ/บัญชีใช้ dialog ยืนยันของแอปแทน window.confirm พร้อมข้อความอธิบายผลข้างเคียงชัดเจน
- ผลกระทบ: โครงสร้างโค้ด front-end ดูแลง่ายขึ้น ผู้ใช้ refresh ไม่โดนเด้งกลับหน้าภาพรวม

## v1.0.7
- วันที่: 2026-10-18
- ปรับปรุง: เพิ่มชุดทดสอบอัตโนมัติ (Vitest) และแยกตรรกะ backend ออกเป็นโมดูลย่อย
- รายละเอียด:
  - เพิ่ม test 43 เคส ครอบคลุมตรรกะเงินสตางค์, ตัวจับ cron/เขตเวลา, การเข้ารหัส credential, และการจับคู่ชื่อบัญชี (ตัดสระไทยผิดใน normalizer ด้วย)
  - CI ต้องผ่าน `npm test` ก่อน build และ deploy ทุกครั้ง
  - ย้ายตรรกะบริสุทธิ์ใน worker ไปเป็นโมดูล (money, cron, timezone, credentials, accountMatch, encoding) ที่ index.ts เรียกใช้ ลดขนาดไฟล์หลักลง
- ผลกระทบ: การแก้โค้ดรอบถัดไปมี test รับประกัน behavior ก่อนขึ้น production

## v1.0.6
- วันที่: 2026-10-18
- ปรับปรุง: เก็บจำนวนเงินเป็นจำนวนเต็มหน่วยสตางค์ในฐานข้อมูล (ทศนิยมไม่คลาดเคลื่อนอีกต่อไป)
- รายละเอียด:
  - คอลัมน์ amount และ balance เปลี่ยนจาก REAL (ทศนิยมลอย) เป็น INTEGER (สตางค์) ผ่าน migration 0006 — ข้อมูลเดิมถูกแปลงอัตโนมัติ
  - การคำนวณยอดบัญชี, ภาพรวม, หมวดหมู่ และกราฟทำบนจำนวนเต็ม แล้วแปลงเป็นบาทที่ขั้นตอนตอบ API หน้าเว็บใช้งานเหมือนเดิม
  - ปิดจ๊อบ CI ให้รัน migration บน database จริงก่อน deploy อัตโนมัติ ไม่ต้องสั่ง npm run db:remote เอง
  - เพิ่ม index (user, type, category) ให้ตาราง transaction เพื่อคิวรีหมวดหมู่ที่เร็วขึ้น
  - ซ่อนรายละเอียด error ภายในจากการตอบกลับ HTTP 500 และบันทึกเต็มไว้ใน log ฝั่งระบบแทน
- ผลกระทบ: ยอดเงินทุกจุดแม่นยำระดับสตางค์ เช่น 10.10 + 20.20 = 30.30 พอดี

## v1.0.5
- วันที่: 2026-10-18
- ปรับปรุง: เข้ารหัส Telegram bot token และ Discord webhook ที่เก็บในฐานข้อมูล
- รายละเอียด:
  - ค่าที่บันทึกใหม่ถูกเข้ารหัส AES-256-GCM ก่อนเก็บใน D1 เช่นเดียวกับ App Password ของ Gmail
  - ค่าเก่าที่เป็น plain text ยังใช้งานได้ และจะถูกเข้ารหัสใหม่เมื่อผู้ใช้บันทึกหน้าการแจ้งเตือนครั้งถัดไป
  - เคลียร์ token ได้โดยลบค่าช่องกรอกแล้วบันทึก
- ผลกระทบ: ข้อมูลการแจ้งเตือนของผู้ใช้ไม่ถูกเก็บเป็นข้อความลอยอีกต่อไป

## v1.0.4
- วันที่: 2026-10-18
- ปรับปรุง: แก้บั๊กช่องว่างเวลา, ช่วงเวลาภาพรวม และการบันทึกการแจ้งเตือน
- รายละเอียด:
  - แก้ตัวกรองภาพรวมรายวัน/รายสัปดาห์ ที่ backend ไม่รับค่า period จึงแสดงยอดเดือนเสมอ
  - ใช้เขตเวลาของผู้ใช้ในการคำนวณยอดภาพรวมและสรุปแจ้งเตือน แทนการ fix ที่ UTC+7
  - แก้การบันทึกการแจ้งเตือนที่ลบ Telegram chat id ที่บันทึกไว้ทิ้งโดยไม่ตั้งใจ
  - ห้ามแก้ประเภทธุรกรรมเป็น transfer ผ่าน PATCH เพราะระบบยังไม่รองรับโอนระหว่างบัญชีจริง
- ผลกระทบ: ยอดภาพรวมตามช่วงเวลาและเขตเวลาถูกต้อง ข้อมูลการแจ้งเตือนไม่หาย

## v1.0.3
- วันที่: 2026-10-18
- ปรับปรุง: เลือกช่วงเวลาภาพรวมและยืนยันรายการจากภาพก่อนบันทึก
- รายละเอียด:
  - เพิ่มตัวเลือกภาพรวมรายวัน รายสัปดาห์ และรายเดือน พร้อมปรับยอดรวม หมวดหมู่ และกราฟตามช่วงเวลา
  - ปรับ AI ให้อ่านรายชื่อบัญชีที่มีอยู่ และจับคำบอกประเภทบัญชี เช่น e-Wallet หรือเงินสดจากข้อความ
  - เปลี่ยนการอ่านภาพเป็นหน้าตรวจสอบข้อมูลก่อนบันทึก ผู้ใช้แก้ยอด บัญชี และประเภทได้ก่อนยืนยัน
- ผลกระทบ: AI จะไม่สร้างรายการหรือปรับยอดบัญชีจากภาพจนกว่าผู้ใช้จะยืนยัน

## v1.0.2
- วันที่: 2026-10-17
- ปรับปรุง: ระบบเลือกบัญชีอัตโนมัติเมื่อ AI วิเคราะห์รายการ
- รายละเอียด:
  - เพิ่มการ normalize ชื่อบัญชีเพื่อให้เปรียบเทียบแบบยืดหยุ่น
  - รองรับ alias ชื่อธนาคารและบัญชียอดนิยม เช่น กรุงไทย, KTB, Krungthai, กสิกรไทย, ไทยพาณิชย์
  - ปรับให้เลือกบัญชีที่ตรงที่สุดแทนการเลือกบัญชีแรกแบบสุ่ม
  - ใช้ฟังก์ชันเดียวกันทั้งกรณี AI วิเคราะห์ข้อความและ AI อ่านสลิป/ใบเสร็จ
- ผลกระทบ: เมื่อลงรายการจากข้อความ เช่น "200 กรุงไทย" ระบบจะเลือกบัญชี "กรุงไทย" ได้ถูกต้องมากขึ้น
